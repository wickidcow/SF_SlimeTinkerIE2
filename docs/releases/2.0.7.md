# SlimeTinker 2.0.7

Promote the previously isolated native item-presentation cleanup into permanent production source and normal project tests. Existing generated names/lore use Adventure components at their final setters. Formatting keeps existing text, order, separators, classic and hex colors; generated item text does not accidentally inherit italics. Explicit formatting is retained.

Tool and armour state logic, material/trait selection, leveling, modifier costs, durability, recipes, Slimefun IDs, persistent key names/types and saved data writers are not redesigned. The public String formatting helpers retain their legacy section-code output protocol. This is not a general tool rebalance or data migration.

The earlier validation branch is retained at 572ab998df93e063a72c4f3ce9c55019c1d1493e. Its temporary source-patching workflow is not required by normal builds and is not promoted. The source renderer and 13 focused generated-text tests are adopted with their original content. Those tests cover presentation, not real-player combat or arbitrary historical worlds.

Synchronize Maven and artifact versioning to 2.0.7 without replacing the existing 2.0.6 release. Normal CI runs actual tests on the supported API lanes, retains their reports, and builds the distributable against Paper 1.21.11 with Java 21 bytecode. Compile-only Legacy and Networks release APIs are checksum-verified and are not shaded. Broader deprecation warnings remain visible.

Publication and complete-bundle runtime validation are separate gates. No production server files or migration defaults are changed by this source update.
